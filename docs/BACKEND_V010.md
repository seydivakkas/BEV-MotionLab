# BEV-MotionLab — backend v0.1.0: implementation evidence and limitations

## Implemented on `feature/backend-v0.1`

- Strict versioned camera calibration and track-detection input validation (`schema.py`)
- Normalized DLT and seeded robust RANSAC with **pixel-unit** inverse reprojection errors (`geometry.py`)
- Independent fit versus holdout reports; holdout is *not* used for fitting
- Pixel-to-metre projection using H, guarded homogeneous division, validated bottom-centre contact proxy
- Variable-timestamp per-track interval speed (km/h); gap invalidation and explicit rejection flags
- Segmentation across invalid contact observations, rather than silently bridging them
- Seeded Monte Carlo refitting from landmark pixel perturbations; explicitly excludes systematic scene bias
- Offline calibrate/analyze CLI, CSV/JSON outputs, SHA-256 provenance manifest, dependency-free BEV SVG
- `unittest` coverage and Windows/Linux Python 3.11/3.12 CI workflow definition

## Local reproduction

```powershell
py -m pip install -e .
py -m unittest discover -s tests -v
py -m bevmotionlab calibrate --calibration examples/synthetic_calibration.json --out runs/calibration.json
py -m bevmotionlab analyze --calibration examples/synthetic_calibration.json --detections examples/synthetic_tracks.csv --camera-id synthetic_cam --out runs/demo
```

## Limits / unfinished engineering work — no frontend approval

- No raw video decode, lens undistortion implementation, or camera-pose drift evidence; input must already be preprocessed and timestamped.
- No independent, measured camera-ground calibration or real speed reference; no real-world RMSE claim.
- Contact points remain assumptions; no reliable automatic occlusion/footpoint/track-ID discontinuity detector.
- Monte Carlo intervals are uncertainty *sensitivities*, not calibration guarantees; no uncertainty intervals attached to every output interval yet.
- No quantitative acceptance baselines, locked adverse-condition sweeps, Windows CI confirmation, package license decision or overall release approval.
- All results generated by fixture names `synthetic_*` are synthetic test evidence, not measured road data.

**Status:** executable backend foundation, module-level automated tests passed locally; full backend gate and independent real-data acceptance remain **HOLD**.

## PTS adapter extension

`bevmotionlab.video.validate_pts` validates strictly increasing video presentation timestamps in ffprobe JSON. `read_ffprobe_pts` invokes a **locally installed optional** FFprobe executable using `subprocess.run` without a shell, a bounded timeout and an explicit local file. It does not decode frames, associate images with detections, or replace the input's source timestamps. A camera-specific timestamp-domain equivalence check remains required before field use.
